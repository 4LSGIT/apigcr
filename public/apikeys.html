Plaintext keys are shown once at creation and stored only as hashes. "Last used" updates at most every 5 minutes per key — it's the instrument for retiring a caller: swap its key, watch the old one go quiet, revoke. Revocation applies immediately on the instance you hit and within ~60s on the rest.

Usage log —

Rows come from jwt_api_audit_log, which records the key's label — not its id. The window is clipped to this key's lifetime, and to the point a later key took the same label, so reused labels don't bleed together. Two keys alive at once under one label cannot be told apart.
Rejected calls never appear here. A revoked or unrecognized key resolves to no label, so it's logged with no username — see Rejected calls above. Silence after revocation is therefore not evidence the caller stopped.

Every request rejected for presenting no usable credential (auth_status = 'unauthorized') — which is where a revoked or wrong x-api-key lands. Expired staff JWTs (invalid_token, mostly browsers) are excluded; at ~4× the volume they'd bury the signal. Role and audience failures are excluded too — those are permissions problems, not credential ones.
There is no key attribution here, and there can't be: the x-api-key header is redacted before the row is written, so the presented key never reaches the table. Match on user agent and IP instead — a caller keeps its UA across a credential change, which in practice is enough to recognize it.
