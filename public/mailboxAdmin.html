How mailboxes work

A mailbox is one email address YisraCase reads over IMAP (and, when a send credential is set, sends from). The row holds only connection data — host, user, secret — so moving a box to another provider is just editing it. Ingest is not live yet: this slice (S0) only sets up mailboxes and who may use them; polling arrives with S1.

Access is per mailbox and per person: read, send, manage (grant others and rename the box). Superusers see everything without a grant. Automations never need one — workflow and sequence sends are not checked against grants.

The secret is write-only. It is stored encrypted and never shown again; leave the field blank to keep it. Changing the host or port requires re-entering it, so a stored password can never be pointed at a different server by an edit.

Folders: each polled folder is stored in full; emit to rules also feeds it into the email-ingest rules pipeline (court mail, case linking). INBOX emits by default. Sent-folder names differ by host (Gmail: [Gmail]/Sent Mail) — add it under the server's exact name.

Adding and editing mailboxes is superuser-only. Mailboxes where you hold Manage appear below — you can change who has access to them.
