How tools work / AI tool prompt

Paste a complete, self-contained HTML file into a tool record. A live tool is served at /tool/<key> on the app origin only — it dead-ends on the marketing domains. Tools run inside the YisraCase shell as iframes and call the real API through the parent's apiSend: staff pin one via Settings → My Custom Tab with path /tool/<key> (use the Copy path action). Opened directly in a browser tab a tool has no parent shell, so every API call fails — that's by design; there is deliberately no open-in-new-tab action here.

AI prompt template 

Create a single, self-contained HTML5 file for an internal tool that runs
as an iframe child of the YisraCase shell. Requirements:

- One complete HTML document, all CSS and JS inline. External libraries only
  from https://cdnjs.cloudflare.com, version-pinned. No other external
  resources.
- The parent window is the authenticated shell. Boot exactly like this — do
  not fetch or manage auth yourself:

    const P = window.parent;
    (function waitForParent() {
      if (P && P.apiSend) return init();
      setTimeout(waitForParent, 100);
    })();

  where init() is your entry point. All API calls go through
  P.apiSend(endpoint, method, payload, extraHeaders, opts) — it returns
  parsed JSON, attaches auth, and handles login/elevation prompting and
  retry itself. On failure it throws an Error with .status and .body; catch
  and surface the message.
- Call EXISTING /api/* endpoints only. Never reimplement server logic
  client-side, and never hardcode data, credentials, or secrets in the HTML.
- Theme with the app's CSS variables: add
  <link rel="stylesheet" href="/theme.css"> and use var(--page-bg),
  var(--surface), var(--text), var(--text-muted), var(--border),
  var(--accent), var(--danger), etc. instead of literal colors.
- Optional: define window.ycBecameVisible = () => { ... } to refetch data
  when the user re-enters the tab (the shell pings visible frames on tab
  open; nothing fires automatically when a hidden iframe is shown).
- Purpose / behavior of the tool: [DESCRIBE WHAT THE TOOL DOES, WHICH
  /api/* ENDPOINTS IT READS OR WRITES, AND WHAT THE UI LOOKS LIKE]
